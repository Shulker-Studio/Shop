# P0 告示牌箱子商店

Status: ready-for-agent
Type: spec

## Problem Statement

基岩版（BDS + LeviLamina）没有告示牌箱子商店。想在服务器里卖东西，目前只有三种做法：把箱子敞开、靠人盯着手动交易、或者装一个只能给 OP 用的商店插件。玩家没法自己开一家明码标价的店，也没法防止自己的库存被人顺手拿走。

Java 版的 ChestShop 生态解决了这件事十几年，但基岩版没有对应物。

## Solution

玩家在箱子旁边的告示牌**正面**写下四行：店主名、份量、价格、商品。服务器校验并规范化这四行，把挨着的容器识别成库存。之后任何人点这块牌子都会弹出一个表单，显示店主、商品、单价和库存，让玩家选买或卖、选几份，确认后钱货两清。

店主不用记格式：第 1 行的名字和第 4 行的商品都由服务器根据"谁写的这块牌子"和"箱子里第一件东西"自动填。非店主既不能改这块牌子的文本、颜色和蜡，也不能打开或拆掉这个箱子。拆掉牌子就关店，箱子立刻恢复成普通箱子。

## User Stories

**开店**

1. 作为店主，我想在箱子旁放下告示牌并写下份量和价格，以便不用任何命令就能开店。
2. 作为店主，我想让服务器自动填我的名字，以便我不用记格式、也不会写错自己的 ID。
3. 作为店主，我想让服务器自动从箱子里取商品名填到第 4 行，以便我不用记物品 ID。
4. 作为店主，我想只写收购价（只写 `S`），以便开一家纯收购店。
5. 作为店主，我想只写出售价（只写 `B`），以便开一家纯出售店。
6. 作为店主，我想同时写两个价格，以便低买高卖赚差价。
7. 作为店主，我想把商店挂在双箱上，以便有 54 格库存可用。
8. 作为店主，我想在同一个方块上挂多块牌子连不同的箱子，以便开一排店。
9. 作为店主，我想在箱子里放好商品再写牌子，以便第 4 行自动就是对的。
10. 作为店主，我想在价格写错时收到一条提示而不是牌子被打掉，以便改一下继续。

**牌面防护**

11. 作为店主，我不想别人改我牌子上的价格，以便我的店不会被劫持。
12. 作为店主，我不想别人给我的牌子染色，以便外观是我的。
13. 作为店主，我不想别人给我的牌子上荧光墨囊或墨囊，以便文字样式是我的。
14. 作为店主，我不想别人给我的牌子除蜡，以便我上了蜡就真的锁住。
15. 作为店主，我想用蜜蜡把牌子锁住，以便连我自己改价都要先除蜡。
16. 作为店主，我想让上蜡不影响交易，以便锁住之后店还能正常营业。
17. 作为店主，我想在牌子已上蜡时仍然能收到钱，以便锁店不等于关店。

**容器防护**

18. 作为店主，我不想别人打开我的商店箱，以便库存不被人顺手拿走。
19. 作为店主，我不想别人拆掉我的商店箱，以便库存不被人端走。
20. 作为店主，我不想别人拆掉我的商店牌，以便我的店不会被别人关掉。
21. 作为店主，我想拆掉牌子就等于关店，以便不需要额外的关店命令。
22. 作为店主，我想在拆掉牌子后箱子立刻变回普通箱子，以便我能马上另作他用。
23. 作为店主，我不想 TNT 炸掉我的商店箱，以便我不会被人一发炸掉全部库存。
24. 作为店主，我想 TNT 照常炸掉商店旁边的方块，以便保护我的店不会让整个服务器像坏了一样。
25. 作为店主，我不想活塞推走我的商店箱。
26. 作为店主，我不想凋灵破坏我的商店箱。
27. 作为店主，我不想火焰烧掉我的商店箱。
28. 作为店主，我不想漏斗从我的商店箱里抽货，以便库存只通过交易流动。
29. 作为店主，我不想漏斗往我的商店箱里塞垃圾。
30. 作为店主，我不想漏斗矿车把我的库存吸走。
31. 作为店主，我不想铜傀儡从我的箱子取货或往里塞东西。
32. 作为店主，我不想投掷器往我的箱子里灌东西。
33. 作为店主，我不想别人拆掉我牌子背后那块墙——那会让牌子掉下来、商店消失。
30. 作为店主，我想自己开箱清点，以便补货和盘点。

**买卖**

31. 作为买家，我想点一下牌子就看到店主、商品、单价、当前库存、我的余额，以便决定买不买。
32. 作为买家，我想选买几份而不是只能买一份，以便一次买够。
33. 作为买家，我想在提交前看到总价，以便不会误买。
34. 作为买家，我想余额不够时什么都不发生，以便不会被扣成负数。
35. 作为买家，我想背包满了被明确拒绝，以便物品不会掉在地上。
36. 作为买家，我想库存不足时按实际能成交的份数成交，以便不用反复试。
37. 作为卖家，我想把东西卖给商店，以便清库存换钱。
38. 作为卖家，我想只能卖箱子认的那种物品（附魔、耐久、自定义名都要匹配），以便店主不会被塞进假货。
39. 作为卖家，我想店主资金不足时被拒绝，以便不会出现"货给了钱没到"。
40. 作为店主，我不想在自己的店里买卖，以便不会自己跟自己交易亏税。
41. 作为玩家，我想连续快速点牌子只成交一次，以便不会被自己的手速刷爆。

**管理员与运维**

42. 作为 OP，我想自己建管理员商店，以便给服务器做一个官方供货点。
43. 作为 OP，我想只有 OP 能建管理员商店，以便普通玩家不能凭空进货。
44. 作为 OP，我想管理员商店同样需要一个容器，以便出处和去向都看得见。
45. 作为 OP，我想能拆掉任何人的商店，以便处理恶意店铺。
46. 作为运维，我想经济后端自动探测，以便装了 LegacyMoney 就自动用上。
47. 作为运维，我想在只装了 LegacyScriptEngine 的服务器上开箱即用，以便不用额外装东西。
48. 作为运维，我想没装 LegacyMoney 时用记分板兜底，以便小服也能跑起来。
49. 作为运维，我想在没有合适后端时明确拒绝而不是假装成功。
50. 作为运维，我想在店主离线、后端又不支持离线记账时禁止交易，以便钱货不会对不上。
51. 作为运维，我想商店能额外收一道税，以便给服务器创收。
52. 作为运维，我想在开启商店税时被明确警告要关掉 LegacyMoney 的 `pay_tax`，以便店主不会被扣两次。
53. 作为运维，我想主干配置改完重启就生效，以便不用学热加载。
54. 作为运维，我想交易失败时有日志可查，以便处理玩家申诉。

**边界**

55. 作为玩家，我想普通告示牌（比如"欢迎光临"）完全不被这个模组碰，以便我在服务器上还能正常写字。
56. 作为玩家，我想在商店牌的背面随便写公告，以便那块牌还能当布告板用。
57. 作为玩家，我想改名之后商店仍然是我的，以便不用重开店。
58. 作为玩家，我想商店牌上显示的是我当前的名字，以便别人认得出来。
59. 作为玩家，我想买东西时看到的商品名是完整名字（即使牌上被截断）。
60. 作为玩家，我想服务器重启后商店原样可用，以便不用重新摆一遍。

## Implementation Decisions

**模块划分**

- `ShopSign`：纯逻辑。把正面四行的文本解析成 `ShopSpec`（份量、价格对、是否管理员店），并把规范化后的文本拼回去。不认识商品名。
- `ShopOwner`：从告示牌正面的编辑者 XUID 得到店主身份与当前显示名。第 1 行文本不参与判定。
- `ContainerFinder`：纯逻辑核心 + 一层 BDS 适配。给定"牌子位置 + 牌子形态 + 该形态的附着目标"，只判断**附着的那一格**是不是容器；双箱合并为一个库存；拒绝已经绑定了商店的容器。不扫邻居。
- `ShopService`：创建 / 编辑 / 销毁、多商店规则、保护判定。
- `TradeService`：预校验、快照、搬物品、转账、补偿。
- `ProtectService`：牌面防护（编辑 / 染色 / 墨囊 / 上蜡 / 除蜡）、容器防护（开箱 / 拆箱 / 拆牌 / 拆依附方块）、破坏防护（爆炸 / 活塞 / 凋灵 / 火焰）、内容防偷（漏斗系 / 铜傀儡 / 投掷器）。
- `EconomyProvider` + `LegacyMoneyEconomy` / `ScoreboardEconomy` / `NullEconomy` / `EconomyManager`。
- `ShopForm`：`SimpleForm` + `CustomForm` 的组装。
- `Config`：JSON 加载与校验。

**纯逻辑不得依赖引擎**

解析器、计价、绑定规则的实现文件不允许 `#include` 任何 `mc/*` 头。这一条是为了让它们可测，也让 BDS 升级不会波及它们。BDS 相关的一切推到 `ContainerFinder` 的适配层、`ShopOwner`、`ProtectService` 和 `ShopForm`。

**事件层**

用 iListenAttentively 的现成事件：告示牌编辑、容器打开、攻击方块、破坏方块、双箱配对、货币变更。它有硬依赖的性质——没装就是 `Shop.dll` 加载失败，不做降级。

自定义 hook 只剩两类：

- **容器内容防偷**：`Hopper` actor 的两个抽取/推出方法（漏斗方块与漏斗矿车共用同一套逻辑，hook 一次覆盖两者）、铜傀儡（`TransportItemsGoal`，靠打开箱子取放）、投掷器（`DropperBlockActor::pushOutItems`）。发射器只发射自己格子里的东西，不碰别的容器，不用管。
- **方块级破坏防护**：爆炸从方块列表里剔除、活塞推动返回失败、凋灵破坏提前返回、火焰不吞。这四条不能用 iListenAttentively，因为它只能取消整场事件，而我们要的是"只有商店箱免疫，旁边照常"。
- **依附方块防护**：拆掉商店牌依附的那块方块会让牌子物理掉落、商店消失，这是非店主绕过"不能拆牌"的路径。判定逻辑是纯的（扫描周围附着的商店牌），对齐 Java 版的 `getAttachedSigns`。

**反复强调的四条语义**

- **牌子正面是唯一的商店载体**。背面不读不写不校验。一块牌最多一个商店。
- **牌子必须附着在容器上**。墙牌看背面、站立牌看下方、悬挂牌看悬挂点——只看这一格，不扫六个邻居。立在箱子旁边地上的牌子不是商店，提示文案要讲清这一点。
- **第 2、3 行玩家说了算，第 1、4 行服务器说了算**。第 1 行是编辑者名字的显示，第 4 行是容器里第一个非空槽位的物品名。
- **数量是"份"**。牌上第 2 行是一份的件数，牌上价格是一份的总价。表单里选份数，总价恒为整数，不出现小数。
- **上蜡不改变商店语义**，只是一个玩家可选的编辑冻结。我们只把"除蜡"纳入店主权限。

**规范化走改包**

编辑提交时直接改写 `PlayerEditSignBeforeEvent` 携带的文本，让服务端和客户端同时拿到规范化结果，不需要事后写回方块实体再刷新。校验失败就取消这个包，牌子保持原样。

**交易顺序**

预校验 → 快照 → 转账 → 搬物品 → 补偿。补偿失败属于严重错误：记日志、通知 OP、冻结该次操作，不自动重试。买卖必须走一次原子转账，不拆成"扣款 + 入账"两步。

**配置**

主干配置 JSON，重启生效。经济后端、记分板目标名、货币符号、商店税率、容器白名单、是否允许店主开箱、交互冷却这些都在配置里。商店税开启时无条件打 WARN 并要求服主手动关掉 LegacyMoney 的 `pay_tax`。

## Testing Decisions

**什么算好测试**

只测外部可观察的行为：给定一段牌面文本，得到什么解析结果；给定一组相邻方块，解析出哪个位置是容器；给定份价和份数，算出什么总价。不测内部函数调用、不测私有字段、不测 hook 有没有被装上。

**测哪些**

- 价格行文法：只有 `B`、只有 `S`、两者都有、`free`、带 `K`/`M` 后缀、小数、负数、零、缺冒号、多余冒号、B 价低于 S 价。
- 份量行：合法整数、0、负数、超过上限、非数字、带空格、Java 的计数格式（应当被拒绝）。
- 份数计价：份价 × 份数、部分成交后的总价、边界（1 份、上限份数）。
- 绑定规则：墙牌看背面、站立牌看下方、悬挂牌看悬挂点；附着格不是容器就返回空；双箱合并；已绑定容器拒绝。
- 管理员商店判定：OP + 配置名 → 管理员店；非 OP + 配置名 → 普通店。

**不测哪些**

BDS 里的行为——弹表单、取消事件、hook 是否生效——靠手工验收清单。这些只能在真实服务器上验证，写不出有意义的自动化测试。

**测试设施**

doctest（header-only），xmake 的 `add_tests`，`xmake test` 跑。仓库目前没有任何测试代码，这是第一处。

## Out of Scope

- 交易流水入库、平均价格、商店统计
- 悬浮字 / 掉落物形式的库存展示
- 商店创建费、退款
- 管理员商店的无容器模式（凭空发货）
- shift 快捷成交（按单价重算任意数量，需要引入小数价格）
- 多语言、GUI 图标美化
- 商店的转让命令
- 玩家名 → XUID 的持久化缓存（不需要，店主身份来自牌子本身）
- 通用箱子锁（ChestLock 保持独立，不在这个模组里合并）

## Further Notes

**三个只能在真实服务器上验证的点**

1. 告示牌每行的像素/字符宽度上限，决定第 4 行商品名会被截到多短。
2. 表单回调的执行线程——方块操作必须回主线程，需要确认 LeviLamina 表单回调的线程语义。
3. 在交互阶段取消 `PlayerInteractBlockEvent` 是否真的阻止 `OpenSignPacket` 发出（理论上会，因为牌子的交互入口在服务端被跳过，但没实测过）。这一点如果不成立，编辑拦截就只剩提交阶段那一道，玩家会看到"打开编辑器、写完、什么都没发生"。
