# 破坏保护做到方块级，故意偏离 Java 版

爆炸、活塞推动、凋灵破坏、火焰对商店箱的影响，用方块级手段处理：从爆炸的方块列表里剔除商店箱、让活塞推动在商店箱处返回失败、让凋灵的破坏在商店箱前提前返回。**Java 版 ChestShop-3 不是这么做的**——它一旦发现爆炸/推动/燃烧列表里含有受保护的箱子，就直接取消整个事件，于是玩家看到的是"附近有商店，整场爆炸哑火"。

这一条是刻意偏离：基岩版的爆炸与活塞范围大、玩家对"爆炸莫名其妙无效"的容忍度低，整场取消会被当成服务器 bug。代价是要自己维护四个方块级 hook，并跟随 LeviLamina 内部符号漂移。ChestLock 的同一组 hook 已在旧版本验证过符号存在且语义正确，因此这不是从零起步的风险。
