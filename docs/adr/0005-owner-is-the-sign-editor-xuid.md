# 店主身份取自牌面的编辑者 XUID，第 1 行只做显示

告示牌每个面都记录了最后一次编辑它的玩家 XUID，那是引擎自己持久化的字段。我们把店主定义为"这块牌的正面最后被谁写的"，第 1 行的玩家名完全由服务器在规范化时覆盖成该 XUID 的当前名字。

这样做的原因是玩家名会变（Xbox gamertag 可以改），而 XUID 不会：按名字匹配意味着店主改名之后自己的商店就认不出自己了，而修复它需要一份必须与牌子同步的外部映射表——那会直接破坏 ADR-0001（牌子即数据源）。XUID 还有个额外好处：引擎按面分别记录，正面与背面各记各的，所以我们只读正面就行，不需要额外字段区分。

代价是玩家不能靠"手写别人的名字"来开店，也不能把商店转让给另一个人——转让只能通过"对方来改这块牌子"完成，而这个动作本身受编辑权限约束。

## 后续（ticket 06「牌面防护」落地后）

上面最后一句的前提已经不成立：06 把“改牌面”收紧成了店主权限（交互阶段拦下 + 提交阶段扔包），所以“对方来改这块牌子”这条路对已存在的商店已经走不通了。P0 的实际口径是：

- **归属在牌子第一次成为商店时写给编辑者，之后改牌面不改归属**（After 阶段按 Before 记下的归属写回），否则 OP 代改一下就能把原店主锁在自己的店外；
- **转让 = 拆牌重开**（拆牌本身是店主权限，DESIGN §9.2）；
- P1 如果要真转让，需要新增一个显式的转让操作，而不是回到“谁改谁得”。
